# สิทธิ์ย้ายวอร์ดเครื่องมือรายบัญชี

แอดมินหลักเปิด **ตั้งค่า → จัดการบัญชี → เพิ่ม/แก้ไขบัญชี → อนุญาตให้ย้ายวอร์ดเครื่องมือ** แล้วบันทึก ใช้ได้ทั้งผู้ใช้ทั่วไปและแอดมิน สิทธิ์เข้าหน้ายืม–คืนหรือแดชบอร์ดยังต้องเปิดแยกตามเดิม

- บัญชีใหม่และบัญชีเดิมทั่วไปเริ่มปิดสิทธิ์ย้ายวอร์ด แอดมินหลักเดิมเริ่มเปิดให้ สามารถเปิด–ปิดได้ทุกบัญชี
- บัญชีปิดใช้งานย้ายไม่ได้ แม้เคยได้รับสิทธิ์
- หน้ายืม–คืนและแดชบอร์ดไม่แสดงปุ่มย้ายหากไม่มีสิทธิ์
- ตรวจโปรไฟล์ล่าสุดก่อนส่งรายการ และฐานข้อมูลตรวจอีกครั้ง ไม่ใช้ JWT metadata เป็นแหล่งสิทธิ์ จึงบล็อกหน้าเก่าที่เปิดค้างหรือการยิง API ตรงหลังถอนสิทธิ์ได้
- การยืม คืน และการแก้เวลาอย่างเดียวใช้กติกาเดิม ประวัติการตั้งสิทธิ์อยู่ในกิจกรรมบัญชี

## ลำดับนำขึ้นระบบ

1. รัน migration `20261022090948_ward_transfer_permission.sql` บนฐานข้อมูลที่ใช้งาน (ตรวจ schema/policies ของ user_profiles แล้ว: ผู้ใช้ SELECT โปรไฟล์ตัวเองได้ แต่ไม่มี policy ให้แก้โปรไฟล์เอง)
2. Deploy Edge Function `mems-user-admin` จาก commit นี้
3. เผยแพร่หน้าเว็บ/JavaScript ของ commit นี้พร้อมกัน และ reload หน้าที่เปิดค้าง
4. แอดมินหลักเลือกเปิดสิทธิ์ให้บัญชีที่ต้องย้ายวอร์ด แล้วทดสอบหนึ่งบัญชีเปิดและหนึ่งบัญชีปิด

ขั้นที่ 1 จะเริ่มบล็อกการย้ายของบัญชีทั่วไปทันที จัดทำในช่วงอัปเดตเดียวกับขั้นที่ 2–4 ห้ามเผยแพร่ `auth.js` ก่อน migration เพราะการโหลดโปรไฟล์ต้องอ่านคอลัมน์ใหม่

## การตรวจสอบ

`npm test` รวมทดสอบสิทธิ์ฝั่ง JavaScript และ SQL จริงใน PGlite: default deny, admin ไม่มีสิทธิ์อัตโนมัติ, active/inactive, ถอนสิทธิ์ขณะ session เดิม, ยิง insert/update ตรง, ห้ามแก้สิทธิ์ตัวเอง, ต้องมีสิทธิ์เข้าหน้า, ไม่กระทบยืม/คืนและการแก้เวลา
