# แบบฟอร์ม PM และตรวจรับ

เมนู `pm-reports.html` ใช้ทะเบียนและบัญชี MEMS เดิม มีประวัติแยกจาก Google Forms เดิม ไม่ส่งอีเมล และไม่แก้ข้อมูลใน Google Forms/Sheets เดิม

## สถานะและการเปิดใช้

1. ใช้ migration `20261028081412_pm_acceptance_reports.sql` และ deploy Edge Functions `mems-report-export` และ `mems-user-admin` จาก revision เดียวกัน
2. ฟังก์ชันเริ่มต้นปิด แอดมินเข้าเมนูเพื่อเปิดได้ ผู้ใช้ทั่วไปต้องได้รับสิทธิ์ `pm_reports` จากแอดมินหลักในหน้าจัดการบัญชีเดิม
3. ผู้ใช้ต้องเลือกผลจริงครบทุกข้อและยืนยันก่อนบันทึก รองรับ PM จากทะเบียนหลาย No. และตรวจรับเครื่องที่ยังไม่มีทะเบียน
4. บันทึกฐานข้อมูลก่อนสร้างไฟล์เสมอ หากยังไม่ได้เชื่อม Drive จะเก็บสถานะ “บันทึกประวัติแล้ว · ยังไม่สร้างไฟล์” แล้วสร้างไฟล์ต่อจากประวัติภายหลังได้

## เชื่อมต่อ Google Drive ครั้งแรก (เจ้าของ Drive ทำครั้งเดียว)

โฟลเดอร์ปลายทางที่สร้างแล้ว: https://drive.google.com/drive/folders/1L3K9n7O1kVabVXxmFrQFAYF0KycMxsK8

1. เปิด https://script.google.com/ ด้วยบัญชีที่เป็นเจ้าของโฟลเดอร์ปลายทางและเข้าถึง Slides ต้นแบบได้ สร้างโปรเจกต์ชื่อ `MEMS PM และตรวจรับ`
2. วางโค้ดจาก `gas/pm-reports/Code.gs` และ manifest `gas/pm-reports/appsscript.json` (Project Settings → Show appsscript.json)
3. Deploy → New deployment → Web app → Execute as **Me** → Who has access **Anyone** แล้วอนุญาตสิทธิ์ Drive/Slides ตามที่ Google แสดง
4. แม้ URL รับคำขอได้ ฟังก์ชันไม่สร้างไฟล์ให้ผู้ไม่ผ่านการตรวจ JWT, บัญชี MEMS, สวิตช์, สิทธิ์ และเจ้าของรายงาน ทุกคำขอตรวจ RLS ใหม่ ห้ามเปลี่ยนเป็นโค้ดที่ไม่ตรวจสิทธิ์
5. คัดลอก URL ที่ลงท้าย `/exec` ลงเมนู PM → ตั้งค่าฟังก์ชัน → บันทึก URL นี้ไม่ใช่รหัสผ่าน ไม่ต้องส่ง Google access token หรือรหัสผ่านให้ MEMS
6. ทดสอบด้วยผลตรวจที่เกิดขึ้นจริงหนึ่งรายการ เปิด Slides/PDF เพื่อตรวจเนื้อหาและตำแหน่ง แล้วจึงใช้งานหลายเครื่อง

ไม่มี service role key หรือ Google token ใน HTML/Apps Script ไฟล์ Code.gs มีเพียง public anon key ของระบบเดิม Script ใช้ JWT ผู้เรียกเพื่ออ่านรายงานที่มีสิทธิ์เท่านั้น ไม่บันทึก token ลง log หรือไฟล์ ไม่มีการเพิ่มสิทธิ์แชร์ไฟล์หรือส่งอีเมล

## ป้องกันซ้ำและข้อจำกัด

- ใช้ UUID คงเดิมระหว่างลองบันทึกซ้ำ ข้อมูลเดิมได้รายการเดิม หากเปลี่ยน payload ด้วย UUID เดิมจะถูกปฏิเสธ
- เก็บ snapshot เลขครุภัณฑ์/ID จากฐานข้อมูลจริง ไม่มี client UPDATE/DELETE รายงาน
- สร้างไฟล์พร้อมกันได้ครั้งละหนึ่งงานต่อ Apps Script มี Script Lock และโฟลเดอร์/ชื่อไฟล์ตาม UUID กดลองรายการเดิมเพื่อสร้างต่อหลังข้อผิดพลาด โดยไม่สร้างไฟล์ที่มีชื่อเดิมซ้ำ
- สถานะกำลังสร้างจะเรียกซ้ำไม่ได้ 10 นาที หากค้างจึงให้ผู้ใช้กดสร้างต่อโดยชัดแจ้ง ระบบไม่ replay งานเขียนอัตโนมัติ
- การส่ง PDF ไป Drive และการอัปเดต DB เป็นคนละบริการ จึงอาจมีไฟล์สำเร็จแต่ลิงก์ยังไม่บันทึก การลอง UUID เดิมจะกู้ไฟล์เดิม
- ไม่ได้สร้างทะเบียนเครื่องมือให้อัตโนมัติเมื่อบันทึกตรวจรับเครื่องใหม่ ให้ใช้เมนูทะเบียนเดิมเพื่ออนุมัติการเพิ่มเครื่อง

## การตรวจ

`npm ci && npm test` รวมการทดสอบ RLS, ปิดฟังก์ชัน, ถอนสิทธิ์, ข้อมูลทะเบียน, ผลตรวจไม่ครบ, UUID ซ้ำ, ตรวจรับเครื่องนอกทะเบียน และสถานะการสร้างไฟล์ด้วย provider จำลอง ทดสอบไฟล์จริงได้ต่อเมื่อเจ้าของเชื่อม Apps Script แล้วเท่านั้น
